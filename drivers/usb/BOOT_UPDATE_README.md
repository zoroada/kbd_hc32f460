# Boot U 盘升级修复

配套工程：E:/HC32F460_FREERTOS/HC32F460_BOOT。

## 使用

1. 用 J-Link 或 pyOCD 将新的 hc32_boot.hex 烧到 Boot 区域。旧 U 盘接收程序有缺陷，不要用它更新 Boot 自身。
2. 运行 HID 后按 PC13 进入升级盘，并松开按键。
3. 将 hc32f460_pinmu.bin 复制到 HC32 UPDATE 盘根目录，只保留一个 BIN 文件。不要复制 HEX，也不要格式化升级盘。
4. 数据和元数据收齐，且约 2 秒无新写入后，Boot 校验并写入应用，成功后自动复位。按键保持按下会使 HID 再次返回 Boot。

升级盘为 128 KB FAT12 内存盘，支持最大 127488 字节（124.5 KiB）的 BIN。内容在断电或复位后丢失；它是临时固件接收盘，不用于普通文件存储。超限或校验失败时不标记升级成功，继续留在 Boot。

## 修改

- boot_disk.c 保存并回读磁盘扇区，按根目录 BIN 文件大小和 FAT12 簇链定位数据，支持乱序、重复、碎片和多扇区写入。
- 检查两份 FAT 一致、文件簇链完整、每个数据扇区确实收到、栈顶和 Thumb 入口有效。
- USB 中断只接收数据；主循环 Boot_UpgradePoll 执行 Flash 操作。
- 写入前擦除启动标志，应用从 0x10000 开始写入，逐块回读校验后最后写 0xFFFC 的 0x44332211 标志，再复位。
- Boot 链接范围限制为 56 KB，预留 0xE000~0xFFFF 的标志扇区，避免未来 Boot 代码增长覆盖它。
- 移除初始化前的跳转打印，用独立汇编完成 MSP 切换，跳转前设置 VTOR 并检查入口地址。
- 调试变量 boot_update_status：0 接收，1 校验，2 写入，3 完成；-1 文件/向量不完整或无效，-3 标志扇区被占用，-4 标志擦除失败，-5 应用擦除失败，-6 应用写入/回读失败，-7 向量回读失败，-8 标志写入/回读失败。

## 验证

ARM GCC 全量编译和链接通过，保留 5 条现有 C 库系统调用链接警告，RAM 未溢出。
历史模拟验证覆盖任意起始簇、碎片、乱序/重复写、多扇区、缺块、FAT 不一致、簇链循环、边界、多个 BIN、真实 HID BIN 重组及最大文件长度；临时测试代码已移除。

尚未实板验证 USB 主机复制、Flash 擦写和模式切换。烧录新 Boot 后，请重新复制 BIN 验证。
